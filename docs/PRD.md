## 1. 背景与目标

### 1.1 背景

个人项目缺乏错误与性能观测手段；市面方案（Sentry 等）偏重、数据出境。需要一个轻量、私有部署、可二次定制的监控平台，同时作为深度技术项目。

### 1.2 目标

- P0：跑通「采集 → 上报 → 存储 → 聚合 → 可视化」完整闭环
- P0：接入本人 3 个真实项目，采集真实数据（拒绝假 demo）
- P1：SourceMap 还原、去重算法演进、采样率
- 非目标（P2）：多租户、告警体系、用户行为回溯

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 开发者（本人） | 查看自己项目的报错与首屏性能，定位线上问题 |
| 前端团队（愿景） | 私有部署，低成本监控内部系统 |

## 3. 功能需求

### 3.1 P0（MVP，必须有）

| 模块 | 功能 | 验收标准 |
|---|---|---|
| SDK | 捕获 JS 运行时错误（window.onerror） | demo 页 `throw new Error()` 后被捕获并上报 |
| SDK | 捕获 Promise 未处理拒绝（unhandledrejection） | `Promise.reject()` 无 catch 时被捕获 |
| SDK | 捕获资源加载失败（img/script/css） | 故意引用 404 图片能被捕获 |
| SDK | 采集 FP / FCP / LCP | 与 Chrome DevTools Performance 面板数值偏差 < 15% |
| SDK | 上报队列：批量 flush + sendBeacon + 失败重发（localStorage） | 卸载场景上报成功率 ≥ 95%（实测记录） |
| SDK | 错误指纹（cyrb53） | 同一错误多次上报指纹一致 |
| 服务端 | POST /api/report 接收入库 | Postman 并发 1000 条无丢失 |
| 服务端 | 错误聚合列表（GROUP BY fingerprint + 分页） | 万级数据 P95 < 200ms（EXPLAIN 验证索引） |
| 服务端 | 错误详情（最近 N 次堆栈） | 正确展示 |
| 服务端 | 性能趋势聚合（按天 AVG） | 数值正确 |
| 服务端 | JWT 登录鉴权 | 无 token 访问 401 |
| 后台 | 登录页 + 项目列表 | 可登录 |
| 后台 | 错误聚合列表 + 详情 | 真实数据驱动 |
| 后台 | 性能看板（ECharts 趋势图） | 7 天曲线正确 |

### 3.2 P1（有余力，加分）

| 功能 | 价值 |
|---|---|
| SourceMap 堆栈还原 | 线上错误可读性的核心能力，展示 Node 侧工程能力 |
| 指纹算法 v2（堆栈关键帧归一化） | 展示算法思维，可对比收敛率 |
| 采样率配置（性能采样） | 展示成本与精度的权衡思考 |
| 虚拟列表渲染万级错误 | 前端性能优化实证 |
| 接口自动化测试（supertest） | 工程规范差异化 |

### 3.3 P2（二期，不承诺）

白屏检测、CLS、长任务监控、用户行为回溯（简化 rrweb）、告警 Webhook、Docker Compose、CI。

## 4. 非功能需求

| 项 | 指标 | 验证方式 |
|---|---|---|
| SDK 体积 | gzip < 8KB | 构建后 gzip 实测，记入 BENCHMARK |
| SDK 兼容性 | Chrome / Edge / Firefox 近两年版本；采集失败时静默降级，不影响宿主页面 | 手动测试 + try/catch 兜底 |
| 上报成功率 | 正常场景 ≥ 99% | BENCHMARK 实测 |
| 后台首屏 | ≤ 1.5s（4G 节流） | Lighthouse |
| 可用性 | 线上 HTTPS 部署，用自己的平台监控自己 | 部署后验证 |
