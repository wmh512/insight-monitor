## 五个问题（先读参考答案，再改写成自己的话，能脱稿讲才算过）

**Q1：资源错误为什么要 capture 阶段监听？普通监听会漏掉什么？**

> 参考答案：资源加载失败的事件**不冒泡**——事件在 img 元素上发生就结束了，不会向上传播。普通 `addEventListener` 默认监听冒泡阶段，在 window 上永远收不到这类事件。必须传第三个参数 `true`（捕获阶段），在事件从 document 往目标元素下行的路上拦截。

**Q2：window.onerror 的 5 个参数里哪个信息量最大？跨域脚本出错时你会看到什么？**

> 参考答案：第 5 个参数 `error` 信息量最大——它带完整调用堆栈（stack），能定位到文件、行号、调用链；`message` 只是摘要。跨域脚本受浏览器同源策略限制，只能收到 `"Script error."`，拿不到堆栈；解法是给 script 标签加 `crossorigin` 属性，且服务端返回 CORS 头。

**Q3：指纹为什么是「message + 堆栈前 3 帧」而不是完整堆栈？**

> 参考答案：完整堆栈含行号，代码热修复会导致行号漂移，同一错误的指纹会不断变化、聚合失效；完全去掉堆栈又会让不同来源的同类 message 混成一个 issue。前 3 帧是在稳定性（扛行号漂移）和区分度（区分不同错误来源）之间的平衡点。指纹 v2（P1）会进一步做堆栈归一化。

**Q4：guard() 包在每层捕获逻辑外面，保护的是谁？不包会怎样？**

> 参考答案：保护宿主页面和 SDK 自身。如果捕获逻辑自己抛错（比如诡异环境下读 navigator 失败），异常会顺着事件处理器影响页面正常运行——**监控 SDK 成为故障源，比没有监控更糟**。guard 把内部异常静默吞掉（debug 模式才打印），保证 SDK 对页面零侵入。

**Q5：Vue 项目为什么还要单独 injectVueErrorHandler，window.onerror 不是已经能抓错误吗？**

> 参考答案：Vue 3 有自己的错误处理机制：组件渲染、生命周期里的错误会被 `app.config.errorHandler` 拦截，配置了它就不一定冒泡到 window.onerror。所以 SDK 提供注入入口，让 Vue 使用方把框架的错误处理接到采集链路上，保证框架内错误不漏。SDK 用结构化类型参数而非 import vue，是为了保持零依赖。
